Implemented journey

  • Personal invitation landing exposes only the inviter's approved display name and network label.
  • Sign-in or account creation with verified email, secure invitation continuation in tab-lifetime session storage, independent invitation review, atomic single-use claim and role assignment. Tokens are removed from the URL/session storage after acceptance.
  • Immediate confirmed relationship reveal and highlighted path using the existing relationship engine; incomplete data produces an honest incomplete-connection message.
  • Optional parent, sibling, child and other-relative builder. Biological/adoptive/full/half/step/unknown assertions are distinguished. Authorized duplicate checks, existing-record selection, autosaved drafts, persistent pending suggestions and live confirmed-tree refresh.
  • Independent parentage review promotes supported biological/adoptive edges. Sibling and step assertions do not invent missing parentage. Cycle checks and typed endpoint constraints protect confirmed ancestry.
  • Voluntary adult invitations: copy-link, email, SMS, WhatsApp and native share where available. Creation sends nothing. Revocation is supported.
  • Guardian request, independent approval and revocation. Minors and unknown-age profiles cannot be invited; their records are restricted to their creator/authorized guardian rather than all network members.
  • Separate network memberships, independent administrator approvals on both sides, personal consent, narrowly scoped profile sharing and immediate revocation. A connection never automatically grants access to an entire other network.
  • Per-network reveal restoration, readable person-focused mobile branch, scroll navigation, zoom and complete overview. Existing interactive/printable templates remain accessible inside the isolated application.

Database and security implementation

Five new migrations live only in local/phase6/supabase/migrations/. The old repository migrations were not applied. The normalized familyconnect schema separates networks/memberships, people/account links, guardians, typed parentage/partnerships, proposals, claims, invitations, progress, connections, receipts and audit records. RLS is enabled on every application table, direct client writes are revoked, and mutation functions validate the authenticated caller and explicit permissions. Private schema objects are not directly exposed through PostgREST.

Invitation tokens use 32 cryptographically random bytes and SHA-256 hashes at rest; raw tokens are excluded from audit/receipt records. New invitations require an independent authorized reviewer. The accepting user's confirmed email must match the invitation; profile ownership is atomic and limited to one claimed identity per account per network. Guardianship is distinct from identity ownership and is never inferred automatically from parentage.

The browser client refuses any backend except localhost/127.0.0.1 on port 55321. The setup helper refuses a linked local workspace or unexpected API URL. Vite uses a separate Phase 6 environment prefix, entry point and build output. The existing hosted .env is not used by this entry. All local seeds use example.test accounts and fictional family data.

Limits requiring review

  • Human usability testing is still needed to establish the 60–90 second onboarding target. Automated timing is reported separately.
  • Identity and guardianship verification use an independently authorized human review/attestation. No external identity-document verification or automated proof of legal guardianship is claimed.
  • Cross-network sharing deliberately supports only the explicitly consented identity profile. Whole-branch sharing, arbitrary field-level grant editing and automatic identity merges are not implemented. Separate networks remain isolated.
  • Full/half/step and other assertions remain pending when supporting parentage is unavailable. The system does not guess relationships to make the tree look complete.
  • Autosave is server-persisted for the active draft, with last-write behavior across simultaneous tabs; collaborative conflict-resolution UI is not implemented.
  • Existing fictional portraits and initials are supported. A new user-media upload service, memory feature and Storage bucket policies were not added in this onboarding slice.
  • Share handlers are available, but real SMS/WhatsApp/email delivery was deliberately not tested. Local links work on this computer only; native sharing depends on browser support.
  • Fixtures include security-test assertions and extra fictional accounts. A rejected cycle attempt remains unconfirmed and never enters the verified graph. This is a review environment, not clean production content.
  • The installed Node 18 runtime emits a Supabase SDK deprecation warning. Upgrade the development runtime before production readiness work.

The existing hosted security findings remain unresolved because hosted changes are prohibited. No claim of production readiness, hosted backup/restore validation, or public deployment is made. Review this local implementation and visual evidence before any further phase.
