PRE-DEPLOYMENT REVIEW · 13 NOVEMBER 2026 · USD

Start free. Keep growth deliberate.

No subscriptions, upgrades, purchases, billable services, hosted migrations or production settings were enabled. Code and database safeguards were tested locally. Provider billing caps and notification recipients remain unverified because no billing dashboard session is accessible. This is a cost plan, not approval or certification for hosted deployment.

Recommended starting arrangement

Use the existing Netlify static deployment configuration on a verified Free account for the first small beta, one Supabase Free project, and a verified-domain transactional email provider on its Free plan (Resend is the priced candidate). Keep development and test databases local. Retain Supabase Auth, private Storage, RLS and existing invitation approvals. No paid chat service, SMS, video hosting, AI API, search service, analytics subscription, image-transformation subscription, database branch or extra hosted project is necessary at launch.

At higher traffic, prefer Cloudflare static hosting on its free allowance before paying for frontend bandwidth. That is a future migration, not an applied change. The hosted image worker is still a deployment blocker: the current Sharp processor is local. Budget a small Netlify Free function allocation for a hosted adaptation, but validate it before relying on this estimate. Netlify binary requests are effectively limited to about 4.5 MB; preserving the current 8 MB image-selection workflow requires client preprocessing below that boundary followed by the same trusted server validation, or an approved alternative host. Do not expose unprocessed uploads or make media public to reduce costs.

Spending caps, alerts and unexpected charges

Application budgets and 70% warning / 90% critical thresholds are configured in cost-policy.json. npm run cost:check -- --local measures local database/storage and explicitly marks unavailable provider metrics UNKNOWN. npm run cost:check -- --usage path/to/provider-usage.json evaluates a fresh provider snapshot; exits nonzero for warnings, stale data or missing metrics. Snapshot shape: {"checkedAt":"ISO timestamp","scope":"provider billing period","usage":{"databaseBytes":123,...}}. Supply every metric named in the policy. Values older than 48 hours fail review. This is an implemented operator-run alert, not a deployed background monitor or an email alert.
